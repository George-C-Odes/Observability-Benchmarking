# Observability Benchmarking Agent Kit

This directory is a Microsoft Agent Package Manager (APM) project containing portable, repository-specific agent primitives.

Local upgrades and the **APM package** CI job share the reviewed CLI pin in [`scripts/apm-version.txt`](../scripts/apm-version.txt).

## Upgrade and refresh

From any working directory, run `python <repo>/scripts/upgrade-apm.py` with Python 3.11+ and Git available. In IntelliJ, run the shared **[upgrade] APM** configuration (Shell Script plugin). From the repository root:

```powershell
python scripts/upgrade-apm.py --dry-run
python scripts/upgrade-apm.py
```

The script installs the exact `apm-cli` pin into the ignored root `.venv-apm/` environment and prints the version and path of the executable it uses. The bare `apm --version` command reports whichever executable is on your `PATH`, which may be a separate system or Scoop installation. From the repository root, verify the CLI used by the upgrade with `./.venv-apm/Scripts/apm.exe --version` on Windows or `./.venv-apm/bin/apm --version` on Unix. Initial installation and dependency staging require network access and any GitHub authentication your environment needs. The CLI version is pinned; pip resolves its transitive Python dependencies.

To adopt a newer stable release, review [upstream releases](https://github.com/microsoft/apm/releases), change `scripts/apm-version.txt` to its exact version, then run the script and review the generated lockfile diff. Runs never select a floating `latest` version or update the audited skill commits.

Renovate proposes stable APM and Modern Web Guidance CLI pin updates for manual review. For a guidance update, review the matching upstream skill commit, update its link in the authored skill, and test search and retrieval. For either update, run the refresh script and include the generated lockfile in the PR.

The refresh stages only `apm.yml` and authored `.apm/` sources in a clean temporary directory, generates a replacement lockfile, verifies unchanged dependency provenance (including commits, hashes, and deployment paths), and runs all four validation commands below. It then adopts the validated candidate lockfile while retaining APM's local ownership state, reconciles local deployments, requires agreement with the clean deployment inventory, and validates again. Existing locally modified managed deployments stop the refresh. A skipped or unmanaged deployment that prevents agreement also fails; reconcile it manually rather than forcing ownership. Authored repository guidance outside `my-agent/` is not generated by this script.

The reviewed 0.36 migration additionally permits APM to carry the catalog's MIT `LICENSE` into the two existing skill deployment roots. The script checks the exact reviewed license hash; all existing skill content and dependency pins must remain unchanged.

Cached 0.36 installs can omit these new license entries from an existing deployment ledger. The script completes only those reviewed entries from clean staging and lets APM materialize missing licenses to establish its local trust baseline. Existing identical license files without that baseline are backed up temporarily; differing local license content stops the refresh. On failure, missing backed-up files are restored.

Failures stop immediately. The original lockfile is restored if the local refresh fails; generated deployments may already have changed and should be inspected before retrying. Temporary staging is removed automatically. If a future CLI intentionally changes dependency deployment layout or lock schema, review and adapt the provenance check separately instead of bypassing it.

On retry, a deployed file matching the validated clean candidate is also accepted, allowing recovery from a partially completed refresh without accepting unrelated local edits.

## Source of truth

- `apm.yml` defines package metadata, targets, and dependencies.
- `.apm/` contains authored instructions, prompts, agents, and skills.
- `apm.lock.yaml` is generated dependency state.
- `apm_modules/` and platform deployment directories are generated and ignored.

Do not edit files under `apm_modules/`. Do not add generated deployments to this package as authored sources.

## Curated dependencies

The package installs only these skills from the MIT-licensed `github/awesome-copilot` catalog:

- `github-actions-hardening` for workflow trust boundaries, expression injection, token permissions, and action pinning.
- `security-review` for cross-language dependency, secret, injection, authentication, and data-flow review.

The catalog is pinned to an audited full commit SHA in `apm.yml`; `apm.lock.yaml` records file hashes. Review upstream changes before moving the pin. Generic Docker, framework, and browser-testing skills are intentionally excluded where they duplicate or conflict with repository-specific guidance.

## Repository-authored skills

- `.apm/skills/benchmark-integrity/SKILL.md` protects comparable endpoint, telemetry, and resource behavior.
- `.apm/skills/focused-validation/SKILL.md` selects failure-mode-appropriate checks and reports validation limits.
- `.apm/skills/ci-report-safety/SKILL.md` covers workflow context validity, scanner/helper trust boundaries, authenticated API URL/credential boundaries, subprocess deadlines, Git-data isolation, fail-closed reports, and scoped security-alert triage with fresh-scan confirmation.
- [Dashboard web guidance](.apm/skills/dashboard-web-guidance/SKILL.md) uses the pinned Modern Web Guidance npm CLI for browser compatibility and UI patterns in `utils/nextjs-dash/`. Update the npm version and the upstream skill reference together after reviewing the release.

The root router and repository contract load these only for matching tasks. They complement the pinned upstream skills with local contracts; do not manually copy them into generated deployments or edit upstream dependency sources. `includes: auto` discovers authored primitives without dependency pin changes, but adding or changing deployed primitives can require refreshed lockfile deployment records.

## Validate

Run from this directory with the pinned `.venv-apm` activated, or invoke its APM executable by path:

```powershell
apm install --frozen
apm compile --validate
apm audit --ci --no-policy
apm pack --dry-run
```

After changing dependencies, regenerate the lockfile before validating:

```powershell
apm lock
apm install --frozen
```

When the CLI pin or authored primitives change, use [the upgrade and refresh script](#upgrade-and-refresh) to regenerate the lockfile and reconcile local deployments. Reserve `--update` and `--refresh` for intentional dependency changes.

The **APM package** job in [Workflow Quality](../.github/workflows/workflow_quality.yml) runs the four validation commands on a clean checkout, checks that the lockfile records the pinned CLI version and survives validation intact, and runs the offline upgrade script tests. It installs the CLI with `microsoft/apm-action` and disables APM lifecycle scripts.

To evaluate an upstream skill update, inspect the available refs and use `apm install --dry-run` before changing the pinned commit:

```powershell
apm view github/awesome-copilot versions
apm install github/awesome-copilot/skills/github-actions-hardening#<commit> --dry-run
apm install github/awesome-copilot/skills/security-review#<commit> --dry-run
```

Use an explicit target to preview placement without writing files:

```powershell
apm compile --dry-run --target copilot --verbose
```

## Design principles

1. Keep repository-wide routing concise in the root `AGENTS.md`.
2. Put reusable agent primitives in `.apm/` and avoid copying large repository documents into them.
3. Preserve benchmark parity across endpoints, telemetry, resources, and service identity.
4. Apply UI guidance only to the Next.js dashboard, not to benchmark services or infrastructure files.
5. Prefer focused validation for the changed subsystem and report commands that actually ran.
